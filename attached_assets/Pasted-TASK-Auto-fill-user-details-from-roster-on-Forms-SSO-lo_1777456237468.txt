TASK: Auto-fill user details from roster on Forms-SSO login (Priority 1 fix)

PROBLEM
When a student logs in via NIAT Forms SSO, our `createOrGetUserByFormsId`
helper creates the user row with a synthetic placeholder email
(`sso_<formsUserId>@forms.local`) and leaves `niatId`, `firstName`,
`lastName`, `campusId` all empty — even when the student is already on
the roster (which has their real email, NIAT ID, full name, campus).

We need to read the roster row and copy those fields into the user row
on first creation, AND one-time-fill them for existing user rows that
are still in the synthetic state.

FILES TO CHANGE
1. lib/db/src/forms-auth.ts  →  rewrite `createOrGetUserByFormsId`
2. (No other files. The caller in artifacts/api-server/src/routes/auth.ts
   already passes the right `provisionedVia` value — leave it alone.)

EXACT NEW BEHAVIOUR for `createOrGetUserByFormsId(formsUserId, opts)`

Step A — look up existing user by formsUserId (same as today).

Step B — look up roster row by `rosterTable.studentId === formsUserId`.

Step C — branch:

  Case 1: NO existing user row
    Create a new user row. Pull every field we can from roster:
      - email:     roster.email?.trim() || `sso_${formsUserId}@forms.local`
      - niatId:    roster.niatId?.trim() || null
      - firstName: split roster.fullName on whitespace → first token (or "")
      - lastName:  split roster.fullName on whitespace → rest joined (or "")
      - campusId:  roster.campusId ?? null
      - role:      "student"
      - provisionedVia: opts.provisionedVia ?? "auto_forms_sso"
    If roster row is null, fall back to the current synthetic-email
    behaviour (only formsUserId + synthetic email + role).
    Return { user: created, created: true }.

  Case 2: existing user row found
    If a roster row also exists, ONE-TIME-FILL only the missing/synthetic
    fields. Build an `updates` object containing ONLY:
      - email:     set to roster.email if (current email matches
                   /^sso_.+@forms\.local$/i) AND roster.email is non-empty
      - niatId:    set to roster.niatId if current niatId is null/empty
                   AND roster.niatId is non-empty
      - firstName: set to first token of roster.fullName if current
                   firstName is empty AND roster.fullName is non-empty
      - lastName:  set to rest-tokens of roster.fullName if current
                   lastName is empty AND roster.fullName is non-empty
      - campusId:  set to roster.campusId if current campusId is null
                   AND roster.campusId is non-null
    NEVER overwrite a field the user (or admin) has already filled in.
    If `updates` ends up empty, skip the update entirely.
    Otherwise: db.update(usersTable).set({...updates, updatedAt: new Date()})
                 .where(eq(usersTable.id, existing.id)).returning()
    Return { user: updatedUser ?? existing, created: false }.

IMPORTANT GUARDRAILS
- Do NOT touch users that have no formsUserId.
- Do NOT touch any field the user already filled in (real email,
  manually-set niatId, etc.). Synthetic-email check is the only
  acceptable trigger for overwriting email.
- Do NOT change the function signature or its return shape.
- Do NOT remove the existing onConflict handling — keep the create path
  race-safe.
- Add `rosterTable` to the imports from "./schema/brave".
