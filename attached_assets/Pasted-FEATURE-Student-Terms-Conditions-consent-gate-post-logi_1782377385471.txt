FEATURE: Student Terms & Conditions consent gate (post-login, blocking) + admin visibility

CONTEXT / STACK
- Monorepo: backend at artifacts/api-server (Express + Drizzle ORM), frontend at artifacts/brave-dashboard (React + wouter + TanStack Query + shadcn/ui), shared DB schema at lib/db/src/schema/brave.ts (Postgres, exported via @workspace/db). Auth gives a current user with a `role` field ("student" | "coordinator" | "admin").
- This must be ADDITIVE and ISOLATED. Do not change or break any existing feature, route, or flow.

GOAL
Force every STUDENT to accept a Terms & Conditions notice once, right after login, before they can use the app. Store acceptance in the DB. Show acceptance status (Yes/No) in the Admin → Users table. Coordinators and admins are NOT gated.

1) DATABASE (lib/db/src/schema/brave.ts, users table)
- Add two nullable columns to the users table:
  - terms_accepted_at  timestamptz (null = not accepted)
  - terms_version      text (store the version string, e.g. "2026-v1")
- Run the drizzle push so the columns are created. Old rows stay null (treated as "not accepted").

2) BACKEND (artifacts/api-server)
- Add POST /api/terms/accept  (auth required):
  - Sets terms_accepted_at = now() and terms_version = "2026-v1" for the currently logged-in user. Idempotent (re-accepting is fine). Returns { ok: true, termsAcceptedAt }.
- Make sure the "current user" response (the endpoint the frontend already calls to load the logged-in user, e.g. /api/auth/me or equivalent) ALSO returns termsAcceptedAt (so the frontend knows whether to show the gate). Add the field to that response/view model.
- In the Admin Users list endpoint (the one that powers /admin/users), include termsAcceptedAt for each user so the table can render Yes/No.

3) FRONTEND — BLOCKING GATE (artifacts/brave-dashboard)
- Create a non-dismissible modal/overlay component (use the existing shadcn Dialog, but disable close: no X button, no Escape-to-close, no click-outside-to-close).
- Mount it in the authenticated app shell/layout so it covers the WHOLE app (it will appear on the Dashboard after login). Render it ONLY when: user.role === "student" AND user.termsAcceptedAt is null/empty.
- While shown, the student must NOT be able to navigate to any other page or use any functionality — the full-screen modal + backdrop must block all interaction behind it.
- Modal content:
  - Title: "Terms & Conditions"
  - Short intro line: "Please read and accept the following to continue."
  - Show these THREE statements as a numbered list, EXACT text:
    1. I acknowledge that NxtWave bears no responsibility or liability for any commercial, financial, or contractual arrangements, payments, or disputes arising from my client engagements under this program.
    2. I agree not to misrepresent NxtWave, including its brand, programs, or offerings, to any client or third party. I understand that any such misrepresentation may result in immediate termination from this program and may attract further legal or disciplinary action as deemed appropriate by NxtWave.
    3. I have read, understood, and unconditionally agree to the [NIAT Program Terms & Conditions], [Privacy Policy], and [NIAT Code of Conduct].
  - In statement 3, render the three bracketed phrases as clickable links that open in a NEW TAB (target="_blank" rel="noopener noreferrer"):
    - NIAT Program Terms & Conditions → https://www.niatindia.com/terms-and-conditions?_gl=1*6gubda*_gcl_au*MjA5MjQ1NzUwMy4xNzU2OTg0MjE2
    - Privacy Policy → https://www.ccbp.in/privacy-policy?utm_source=niatindia-website&utm_medium=website&utm_campaign=footer-legal-privacy-policy&invite_code=TP3YSU
    - NIAT Code of Conduct → https://www.niatindia.com/terms-and-conditions?_gl=1*6gubda*_gcl_au*MjA5MjQ1NzUwMy4xNzU2OTg0MjE2   (use the NIAT T&C page for now; replace if a dedicated URL is provided)
  - NO checkboxes. A SINGLE button at the bottom labeled: "I Understand and Agree".
  - On button click: call POST /api/terms/accept, show a spinner/disable the button while pending, then on success update the cached current-user (so termsAcceptedAt is now set) and close the modal — the app unlocks. On error, show a toast and keep the modal open.
- A student who has already accepted (termsAcceptedAt set) must NEVER see the modal again. Coordinators/admins never see it.

4) ADMIN USERS TABLE (artifacts/brave-dashboard, /admin/users page)
- Add a new column header "Terms".
- For each user row, display "Yes" if termsAcceptedAt is set, otherwise "No". Display only — no actions, no editing. (Optional: green text for Yes, muted/red for No.)

ACCEPTANCE CRITERIA
- A student with no acceptance logs in → lands on Dashboard → blocking modal appears → cannot click/navigate anything else.
- Clicking "I Understand and Agree" saves to DB, closes the modal, and unlocks the app; refreshing or re-logging in does NOT show it again.
- Coordinators and admins are never gated.
- Admin → Users shows a "Terms" column with Yes/No for every user.
- No existing functionality is changed or broken; the feature is fully additive.
