Yes — cleanly, and with no APK rebuild. You already have most of the plumbing.

What exists today
page_views already logs every navigation: userId, role, path, createdAt. It just doesn't record where from.

And the frontend already knows — isNativeApp() checks window.Capacitor.isNativePlatform(), which is exactly the app-vs-browser answer, and it's already used all over the codebase.

The change — about 15 lines
One nullable column: page_views.platform — 'app' | 'web', ADD COLUMN IF NOT EXISTS
Client sends platform: isNativeApp() ? "app" : "web" in the existing recordPageView call
Server stores it, defaulting to null when absent
Additive and safe: nullable column, existing rows unaffected, and if the field is missing nothing breaks. No API contract change for any other route, no auth change, no APK — isNativeApp() lives in src/, so it ships with a normal deploy.

What you'd then be able to answer
"How many are using the app" — accurate, immediately:


select count(distinct user_id) from page_views
where platform = 'app' and created_at > now() - interval '30 days';
Daily/weekly active, app vs web split, which screens they use in the app — all fall out of one column.

"How many installed" — ⚠️ this one you cannot truly measure. No web app can. Best you get is two proxies:

Ever-opened = count(distinct user_id) where platform='app'. Accurate for people who opened it at least once, but misses anyone who installed and never launched, and can't see uninstalls.
Download count — currently zero visibility, because brave-app.apk is served as a static file. Counting it needs a small route (/api/app/download → log, then redirect to the file) and pointing braveAppDownloadUrl at it. Also additive.
Downloads ≠ installs either — some downloads never install, and one person can download twice. The honest metric is ever-opened, and I'd report it as that rather than "installs".

One caveat on backfill
The column only starts collecting from the day you deploy it. Everything before that is null — unknowable, not zero. Worth labelling that in whatever report you build, or the first month's chart will look like the app launched the day you shipped the tracking.
