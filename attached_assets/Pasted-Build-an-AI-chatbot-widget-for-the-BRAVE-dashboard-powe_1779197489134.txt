Build an AI chatbot widget for the BRAVE dashboard, powered by the Cerebras API.

Create a floating chatbot that appears on the landing page, the login page, and inside the logged-in dashboard. It answers BRAVE-programme questions using a knowledge-base file and the Cerebras LLM.

1. Knowledge base file
Create a plain-text file brave-knowledge.txt in the repository root.
Fill it with a thorough, well-organised knowledge base about the BRAVE programme — compile it from the existing content in the app: the landing page FAQ/sections, replit.md, programme rules (teams, projects, order book, revenue entries, verification flow, leaderboard, weekly journals, Demo Day, eligibility threshold, roles), and how students use the dashboard. Write it as clear Q&A / sections so the LLM can answer from it.
2. Backend — Cerebras-powered endpoint
Add a new route file artifacts/api-server/src/routes/chatbot.ts and register it in the routes index.
Endpoint: POST /api/chatbot/ask, body { message: string, history?: { role: "user" | "assistant", content: string }[] }.
On startup (or first call) read brave-knowledge.txt into memory.
Read the Cerebras API key from process.env.CEREBRAS_API_KEY. If missing, return a friendly error — never crash.
Call the Cerebras API: POST https://api.cerebras.ai/v1/chat/completions, header Authorization: Bearer ${CEREBRAS_API_KEY}, model llama3.1-8b.
System prompt = instructions + the full brave-knowledge.txt content. Instruct the model:
"You are the BRAVE programme assistant. Answer ONLY using the knowledge below. If the answer isn't in it, say you don't have that info and suggest contacting the Campus Coordinator. Never invent facts."
Scope by auth state — detect with req.isAuthenticated():
Not logged in (landing/login visitors): give a short, helpful general answer; for anything detailed or account-specific, end with a line telling them to log in to the dashboard for full details.
Logged in (dashboard): answer fully and in detail.
Tell the model to reply as strict JSON: { "answer": string, "suggestions": string[] } where suggestions is 2–3 short follow-up questions related to the user's question.
Parse the JSON; if parsing fails, treat the whole text as answer and return empty suggestions. Catch all errors and return a friendly fallback message.
Add a modest rate limit on this endpoint.
3. Frontend — chatbot widget component
Create a reusable component artifacts/brave-dashboard/src/components/chatbot.tsx:

A floating circular avatar/chat button fixed at bottom-right. Click toggles a chat panel open/closed.
Chat panel contains:
A small header (title + close button).
A scrollable messages area: user messages aligned right, bot responses aligned left, with chat bubbles.
On open (empty state): a greeting message + 3 default suggested questions as clickable chips.
After every bot response, render 2–3 suggested follow-up question chips (from the API's suggestions) just below that response. Clicking a chip sends it as the next question.
A typing / "one sec…" indicator while waiting for the reply.
An input row at the bottom: a text input on the left and a send icon button on the right. Enter key sends the message (laptop); clicking the send icon also sends.
Sending a message → fetch("/api/chatbot/ask", { method: "POST", credentials: "include", headers: {"content-type":"application/json"}, body: JSON.stringify({ message, history }) }) → append the bot's answer and show its suggestions.
Keep the recent conversation in history and pass it back so the bot has context.
Style it cleanly with the BRAVE brand colours (red/orange); make sure it looks good on both the dark landing/login pages and the light dashboard.
4. Mount the widget in 3 places
artifacts/brave-dashboard/src/pages/marketing/landing.tsx
artifacts/brave-dashboard/src/pages/auth/login.tsx
The dashboard layout artifacts/brave-dashboard/src/components/layout.tsx (so it shows on all logged-in student pages).
5. Behaviour summary
Landing & login (logged out): answers general BRAVE questions briefly; nudges users to log in for detailed/account-specific info.
Dashboard (logged in): answers anything fully from the knowledge base.
6. Finish
Do not change any existing features, cron jobs, or email logic.
Run a typecheck on both packages and confirm they compile.
