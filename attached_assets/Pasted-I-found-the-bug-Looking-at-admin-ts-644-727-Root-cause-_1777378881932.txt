I found the bug. Looking at admin.ts:644-727:

Root cause: the PATCH handler references a variable target (lines 694 and 702 — target.studentId, target.email) but target is never declared anywhere in the function. There's no SELECT of the existing roster row before the update. This is a ReferenceError at runtime, Express's default error handler catches it, and returns the generic HTML Internal Server Error page you're seeing in the toast.

Here's the Replit prompt:

Replit Prompt: Fix HTTP 500 on PATCH /admin/roster/:id (Edit Roster Entry)
The Edit roster entry dialog on /admin/roster returns HTTP 500 with the default Express HTML error page. The bug is in artifacts/api-server/src/routes/admin.ts inside PATCH /admin/roster/:id (around line 644).

Bug
Lines 694 and 702 reference an undefined variable target:


if (target.studentId) { ... }
if (!linkedUserId && target.email) { ... }
There is no target declared in this handler — the existing roster row is never fetched. Every edit therefore throws ReferenceError: target is not defined and Express returns 500.

Fix
Inside PATCH /admin/roster/:id, after validating id and parsing the body, but before running the UPDATE:

Select the existing roster row first and store it as target:


const [target] = await db
  .select()
  .from(rosterTable)
  .where(eq(rosterTable.id, id));
if (!target) {
  res.status(404).json({ error: "Roster entry not found" });
  return;
}
Place this between the safeParse block and the set object construction.

Keep the rest of the handler the same — target.studentId / target.email references will now resolve correctly.

Remove the email-based fallback when resolving the linked user (if (!linkedUserId && target.email) { ... }). Match the linked user only by target.studentId → users.formsUserId. Reason: matching by email is unsafe if duplicate emails are allowed in the roster — it could mutate a different student's user row.

Wrap the db.update(rosterTable) and db.update(usersTable) calls in a try/catch. On Postgres unique-violation (error code 23505):

If the constraint name is on roster.student_id, return 409 with { error: "A student with this Student User ID already exists" }.
Otherwise return 409 with { error: "Conflict: a unique field already has this value" }.
Empty-string handling: if updates.email === "", set it to null before persisting (don't try to write an empty string into a column that may be unique). Same for niatId and batchSectionName.

Remove (or keep nullable) any logic that synthesizes sso_<studentId>@forms.local into users.email during the mirror update — only update users.email if updates.email is non-empty.
