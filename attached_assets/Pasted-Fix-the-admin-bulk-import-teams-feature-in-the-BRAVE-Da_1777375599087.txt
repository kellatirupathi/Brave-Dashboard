Fix the admin bulk-import-teams feature in the BRAVE Dashboard so it validates Student User IDs against the roster table (not the users table) and auto-provisions the user row from roster data when creating teams. Apply the same fix to the single "Add Team" admin endpoint as well.

=== CONTEXT — WHY THIS FIX ===
The current admin team-import flow (POST /api/admin/teams/bulk-import and POST /api/admin/teams) validates each Student User ID by checking if it exists in the users table. But the users table is only populated AFTER a student logs in via Replit OIDC for the first time. Real source-of-truth for enrolled students is the roster table — admins bulk-imported all 7,500+ student profiles there earlier (each row has studentId UUID + niatId + fullName + email + campusName + batchSectionName).

Result today: a CSV containing legitimate enrolled students all gets skipped with "User not found" because no users-table row exists yet. The team must be createable now so that when the student finally logs in, they immediately see the team on their account.

Stack context: pnpm monorepo. lib/db/src/schema/brave.ts has both `users` and `roster` tables. Both have a UUID id column; the CSV's "Student User ID" column matches roster.studentId (which is the same UUID that becomes users.id when the student logs in for the first time — the auth flow already does this idempotent matching). lib/db/src/schema/auth.ts is unchanged.

=== BUSINESS RULES (confirmed) ===
1. The Student User IDs in the CSV are roster.studentId values. Roster is the validation source.
2. If a Student User ID is in roster but NOT yet in users, AUTO-PROVISION a users row from roster data at team creation time, so the team membership can be inserted and the student is linked instantly when they log in.
3. If a Student User ID is NOT in roster either → skip the row with reason "User not found in roster: <id>".
4. If a user (whether existing in users or newly provisioned) is already on another team → skip the whole row with reason "User already in team: <id>".
5. Existing student-driven team creation, coordinator approval, all other flows must remain UNCHANGED.
6. Do NOT modify the database schema. No migrations.

Add this helper near the top of admin-teams.ts:

  /**
   * Resolves a Student User ID to a users-table row. If the user does not yet
   * exist (the student hasn't logged in), provisions them from roster data so
   * that team membership can be inserted right away.
   *
   * Returns:
   *   { ok: true, userId, campusId } when the user is ready to be added to a team
   *   { ok: false, reason } when the id is not in roster, or any other validation fails
   */
  async function resolveOrProvisionUser(studentUserId: string): Promise<
    | { ok: true; userId: string; campusId: number | null }
    | { ok: false; reason: string }
  > {
    if (!studentUserId || !studentUserId.trim()) {
      return { ok: false, reason: "Empty user id" };
    }

    // 1. Already in users table? Done.
    const [existing] = await db
      .select()
      .from(usersTable)
      .where(eq(usersTable.id, studentUserId));
    if (existing) {
      return { ok: true, userId: existing.id, campusId: existing.campusId ?? null };
    }

    // 2. Not in users — try roster.
    const [rosterRow] = await db
      .select()
      .from(rosterTable)
      .where(eq(rosterTable.studentId, studentUserId));
    if (!rosterRow) {
      return { ok: false, reason: `User not found in roster: ${studentUserId}` };
    }

    // 3. Resolve campus from roster (campusId on roster row, or look up by campusName).
    let campusId: number | null = rosterRow.campusId ?? null;
    if (!campusId && rosterRow.campusName) {
      const [c] = await db
        .select()
        .from(campusesTable)
        .where(eq(campusesTable.name, rosterRow.campusName.trim()));
      campusId = c?.id ?? null;
    }

    // 4. Split fullName into first/last (best effort).
    const fullName = (rosterRow.fullName ?? "").trim();
    const parts = fullName.split(/\s+/);
    const firstName = parts[0] ?? "";
    const lastName = parts.slice(1).join(" ") || "";

    // 5. Insert the users row with the SAME id as the roster studentId so that
    //    when the student later logs in via OIDC, the existing flow links them
    //    correctly.
    await db.insert(usersTable).values({
      id: studentUserId,
      email: rosterRow.email ?? `${studentUserId}@placeholder.brave.local`,
      firstName,
      lastName,
      role: "student",
      campusId,
      niatId: rosterRow.niatId ?? null,
      isActive: true,
      provisionedVia: "manual",
    });

    return { ok: true, userId: studentUserId, campusId };
  }
