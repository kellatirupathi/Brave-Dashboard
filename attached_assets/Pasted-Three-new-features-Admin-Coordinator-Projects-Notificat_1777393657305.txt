DELETE /api/projects/:id (admin only) — cascade inside a single db.transaction(): order_book_entries → revenue_entries → projects row. Wrap in try/catch; PG 23503/23505 → 409. logAudit("delete_project", ...).

FEATURE 3 — Capture Student profile fields on team creation
When a student who has just signed in for the first time tries to Create your team, the create-team form must additionally collect Full Name, Email, and NIAT ID so the user record gets enriched on save.

3.1 Frontend — artifacts/brave-dashboard/src/pages/get-started.tsx (or wherever the "Create your team" form lives)
Restructure the form into three rows:


Row 1:  [ Team name        ]   [ Campus (Select)            ]
Row 2:  [ Tagline (optional, full-width)                    ]
Row 3:  [ Full Name        ]   [ Email ]   [ NIAT ID        ]
Field rules:

Team name — required, max 60 chars (existing).
Campus — required Select; height-capped scroll (max-h-72 overflow-y-auto).
Tagline — optional, max 120 chars (existing).
Full Name — required, min 2 chars. Pre-fill from user.firstName + " " + user.lastName if already present (so existing users don't need to retype).
Email — required, must match email regex. Pre-fill from user.email if present.
NIAT ID — required, min 3 chars. Pre-fill from user.niatId if present.
If all three profile fields are already filled on the user record, the inputs render in a collapsed read-only summary with an "Edit profile" toggle — so existing users with a complete profile keep the simpler 2-row form, and only first-time students see the expanded form.

Submit handler: call the new combined endpoint (below) instead of the existing POST /api/teams. On success, invalidate the useAuth/getMe query so the navbar avatar/name updates immediately, then route to /team.

3.2 Backend — artifacts/api-server/src/routes/teams.ts
Replace or augment the existing POST /api/teams handler so it accepts the three extra fields:


{
  name: string,
  campusId: number,
  tagline?: string,
  // NEW — required when the user record is missing any of these:
  fullName: string,
  email: string,
  niatId: string,
}
Inside a single db.transaction():

Split fullName on whitespace → firstName (first token) + lastName (rest joined). Trim everything.
Update the users row for req.user.id with the supplied firstName, lastName, email (lowercased), niatId (trimmed), campusId. Only overwrite a field if the supplied value is non-empty.
Validate uniqueness:
If another user already has the same niatId → return 409 { error: "This NIAT ID is already registered to another account." }.
The current users.email UNIQUE constraint stays as-is for now — if conflict, return 409 with { error: "This email is already registered to another account." }.
Insert the team row (status pending per existing flow) with the leader = req.user.id.
Insert the leader into team_members.
Insert the auto-milestone "Team registered" (existing logic).
logAudit("create_team_with_profile", "team", team.id, ...).
If the transaction fails for any reason, roll back and return a clean 4xx/5xx with { error } JSON — never a generic HTML 500.

Backwards compatibility: if all three new fields are omitted and the user record already has full profile data, accept the request as before.
