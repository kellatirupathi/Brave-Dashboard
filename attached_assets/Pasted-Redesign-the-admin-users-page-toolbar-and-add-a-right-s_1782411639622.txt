Redesign the /admin/users page toolbar and add a right-side Filters panel with new server-side filters. Stack: pnpm monorepo, Express + Drizzle + Postgres backend, React + Vite frontend, API types generated by Orval from an OpenAPI spec. Don't change any existing features — only restructure the toolbar and add filtering.

1. Toolbar layout — artifacts/brave-dashboard/src/pages/admin/users.tsx
Currently the header row has: search input, inline Role <Select>, inline Source <Select>, <CampusCombobox>, a 3-dots <DropdownMenu>, and the Add User button. Restructure the right side to exactly: Search input | "Filters" button (with Filter icon from lucide-react) | 3-dots menu | Add User button. Remove the three inline Role/Source/Campus selects from the toolbar — they move into the new panel.

2. Right-side Filters panel (use the existing @/components/ui/sheet.tsx)
Clicking the Filters button opens a <Sheet side="right"> full-height panel containing ALL filters. Keep existing ones (Role, Source, Campus) and add new ones:

Status — Active / Inactive / All (maps to isActive)
Campus ID — text input (maps to niatId, case-insensitive contains)
Logins — two number inputs: min and max (maps to loginCount)
Terms — Accepted / Not accepted / All (maps to termsAcceptedAt null check)
Last login — from-date and to-date inputs (<input type="date">)
Last seen — from-date and to-date inputs
Panel footer: "Apply" and "Clear all filters" buttons. Show a small count badge on the Filters button = number of active filters. Reset page to 1 whenever any filter changes.
3. Applied-filter chips (above the table)
When any filter is active, render a row of chips with red text (e.g. text-red-600 border-red-200 bg-red-50), each labelled like Status: Active, Logins: 1–5, Last login: 2026-06-01 → 2026-06-25, each with an × to clear just that one, plus a "Clear all filters" link. Hide the row when no filters are active.

4. Backend — extend the API (server-side filtering, must work across all 4,602 users with pagination)

a) OpenAPI spec lib/api-spec/openapi.yaml, operation listUsers (GET /admin/users): add query params — status (enum active|inactive), niatId (string), minLogins (integer), maxLogins (integer), terms (enum accepted|not_accepted), lastLoginFrom, lastLoginTo, lastSeenFrom, lastSeenTo (all string date YYYY-MM-DD).

b) Regenerate codegen so ListUsersQueryParams (in @workspace/api-zod) and the useListUsers hook (in @workspace/api-client-react) pick up the new params:
pnpm --filter @workspace/api-spec run codegen

c) Route handler artifacts/api-server/src/routes/admin.ts, GET /admin/users (~line 231): destructure the new params from queryParams.data and push Drizzle conditions onto the existing conditions array (import gte, lte, isNull, isNotNull from drizzle-orm). Column mapping on usersTable: status→eq(isActive, status === "active"); niatId→ilike(usersTable.niatId, '%'+niatId+'%'); minLogins→gte(loginCount, n), maxLogins→lte(loginCount, n); terms==="accepted"→isNotNull(termsAcceptedAt), "not_accepted"→isNull(termsAcceptedAt); date ranges use gte/lte on lastLoginAt / lastSeenAt (treat to date as inclusive end-of-day). Leave all existing role/campusId/provisionedVia/search/pagination logic untouched.

5. Frontend wiring
Pass the new filter state into useListUsers({...}) alongside the existing params. Also include the new params in the CSV export query-string builder (the export-all-matching-filters block) so export respects the active filters.
