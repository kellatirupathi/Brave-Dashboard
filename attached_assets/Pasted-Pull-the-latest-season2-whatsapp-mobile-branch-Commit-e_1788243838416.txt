Pull the latest season2-whatsapp-mobile branch. Commit e933f87 replaces the
mobile app's Chrome Custom Tab login with an in-app WebView. Do not redesign
it — it is implemented and TypeScript passes. Build and verify it.

WHY THE OLD FLOW COULD NEVER WORK
NxtWave Forms decides its own post-login destination. /api/auth/generate-token
accepts { user_id } and nothing else — there is no callback field, so the
redirect_uri we appended was ignored. The Custom Tab landed on the website and
the app was never told anything. That is the blank page students saw. It is
NOT fixable by whitelisting a deep link, and not fixable in the app's own code.

WHAT THE NEW FLOW DOES
src/screens/WebLoginModal.tsx opens the Forms login in a WebView the app owns,
so it can read the URL and cookie jar directly. Two ways to recover a session:
  1. Landing URL carries ?auth_token=... -> exchange via /api/auth/validate-token
  2. Otherwise read the `sid` cookie for dashboard.brave.niatindia.com and store
     it in the Keystore (src/lib/session.ts -> adoptSessionFromCookies)
Route 2 needs nothing from NxtWave: it does not care how the session was made,
only that it exists.
