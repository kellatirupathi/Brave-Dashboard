Add app-vs-web usage tracking, surfaced as a new "User Stats" section in Admin Config.

TRACKING (additive only — must not change any existing behaviour)
1. Schema (lib/db/src/schema/brave.ts): add a NULLABLE column to page_views:
     platform: text("platform")   // 'app' | 'web' | null
   Push with ADD COLUMN IF NOT EXISTS. No backfill — rows from before this
   shipped are UNKNOWN, not 'web'.

2. Client (src/lib/page-views-api.ts): send the platform in the existing
   recordPageView call:
     body: JSON.stringify({ path, platform: isNativeApp() ? "app" : "web" })
   isNativeApp() already exists in src/lib/native-auth.ts.

3. Server (routes/page-views.ts):
   - POST /page-views: widen the body schema with
     platform: z.enum(["app","web"]).optional(), and store it. Must stay
     optional so an older cached bundle cannot break the insert.
   - Add GET /admin/user-stats returning, for a date range:
       appUsers        count(distinct user_id) where platform='app'
       webUsers        count(distinct user_id) where platform='web'
       appShare        percentage of views from the app
       everOpenedApp   count(distinct user_id) where platform='app', all time
       perPath         existing path rows plus appViews / webViews columns
       trackingSince   min(created_at) where platform is not null

4. Regenerate the API contract:
     pnpm --filter @workspace/api-spec run codegen

ADMIN UI — new Config section
5. In pages/admin/config.tsx add ONE new entry to the SECTIONS array:
     { id: "user-stats", slug: "user-stats", label: "User Stats", icon: BarChart3 }
   Each section already has its own URL, so this gives:
     /admin/season/2.0/config/user-stats
   Render its pane the same way the other sections do:
     {activeSection === "user-stats" && <UserStatsCard />}

6. New components/user-stats-card.tsx:
   - Range selector: 7 / 30 / 90 days, default 30
   - Four tiles: App users · Web users · App share % · Ever opened the app
   - Table of screens with App / Web / Total columns, sorted by total
   - A "Tracking since {date}" line, so the first weeks are not misread as
     the app having launched that day
   - Match the styling of the existing Config cards

NAMING
Call the metric "Ever opened the app", NEVER "installs". A web app cannot see
installs: this misses anyone who installed without launching, and cannot see
uninstalls.

DO NOT
- Do not add a download counter — brave-app.apk is a static file and downloads
  are not installs; out of scope.
- Do not touch any other Config section, the page-view recording path for
  existing callers, APIs, permissions, routing, or the season logic.
- Do not backfill platform for historical rows.

VERIFY
- pnpm run typecheck and pnpm run build pass.
- /admin/season/2.0/config/user-stats and the 1.0 equivalent both load.
- Existing page-view recording still works with platform absent.
