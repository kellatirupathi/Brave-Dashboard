Here's the process that worked before — and it's the answer.

What the Capacitor app was actually doing
It wasn't doing anything clever. It was the website. The whole UI you saw — Dashboard, Journal, Leads, your team "Autosolutionsindia", rank #376 — was dashboard.brave.niatindia.com rendering inside a WebView.

And the login was the ordinary web login, not Forms SSO:


/api/login  →  Replit OIDC  →  /api/callback
            →  createSession()  →  setSessionCookie(sid)
            →  redirect back to the dashboard, logged in
/api/callback ends with exactly the two lines that matter:


const sid = await createSession(sessionData);
setSessionCookie(res, sid);
That's a real sid cookie on your own domain — the same credential my React Native app already knows how to store and use.

Why I went wrong
VITE_FORMS_LOGIN_URL wasn't set back then, so the web app fell through to login() → /api/login. That path worked every day.

When Replit set that variable, both apps switched to the Forms path — which was never finished, has no callback field, and can't hand a session to an app. We've been debugging the broken road while the working one sat next to it.

The OTP flow you just completed is Forms. The flow that logged you in before is Replit OIDC.

What to do
Point the WebView at /api/login instead of the Forms URL.

Everything else I built already fits:

The WebView completes the OIDC flow
/api/callback sets sid on dashboard.brave.niatindia.com
adoptSessionFromCookies() lifts it into the Keystore
The app closes the WebView and shows native screens
No token exchange, no deep link, no redirect URI, nothing from NxtWave. It's the same login the website has always used.
