You are working on the "BRAVE Program Dashboard" — a production, full-stack pnpm-workspace monorepo (TypeScript) that is LIVE with ~7,500 students and many admins. Stack: Express 5 API in `artifacts/api-server` (mounted at `/api`), React + Vite + Tailwind + shadcn/ui frontend in `artifacts/brave-dashboard` (routing via `wouter`, data via `@tanstack/react-query`), and Drizzle ORM + Postgres schema in `lib/db/src/schema/brave.ts`. There are 3 roles in `userRoleEnum`: `student`, `coordinator`, `admin`.

GOAL: Add a "Super Admin" capability on top of the existing `admin` role, plus a per-page permission system that super admins use to control what each normal admin can do.

NON-NEGOTIABLE SAFETY RULES (this is in production):
- Make ALL changes ADDITIVE and BACKWARD-COMPATIBLE. Do not break any existing behavior.
- Do NOT touch the `student` or `coordinator` roles, their pages, flows, logins, or permissions in any way. This is admin-only.
- Use DEFAULT-ALLOW everywhere: an admin with no stored permission record must have FULL access (exactly like today). Every existing admin must keep working identically until a super admin explicitly restricts them.
- Do NOT add a 4th role value to the enum and do NOT rewrite the ~20+ existing `req.user.role === "admin"` checks. Instead, a super admin is an `admin` with an extra boolean flag — so all existing admin checks keep passing unchanged for both admins and super admins.
- Keep the existing "Add User" modal code in place (dormant) as a fallback; just point the button to the new page.

DATA MODEL (additive columns on the `users` table in `lib/db/src/schema/brave.ts`):
- `isSuperAdmin: boolean("is_super_admin").notNull().default(false)` — an admin with full, unrestricted access who can manage other admins.
- `adminPermissions: jsonb("admin_permissions")` (nullable) — `null` means FULL access (default for every existing admin). Otherwise a JSON map keyed by page href: `{ "/admin/teams": { view, edit, delete, hidden }, ... }`.
(These columns must be pushed to the DB before the new code runs, because queries select them.)

PAGE REGISTRY (the permission key for each page is its route href). Define this list on BOTH server and client and keep them in sync:
/admin (Dashboard), /admin/queue (Review Queue), /admin/team-requests (Team Requests), /admin/teams (Teams), /admin/projects (Projects), /admin/roster (Roster), /admin/leaderboard (Leaderboard), /admin/heatmap (Heatmap), /admin/journals (Journals), /admin/demo-day (Demo Day), /admin/campuses (Campuses), /admin/users (Users), /admin/new-users-requests (New User Requests), /admin/announcements (Announcements), /admin/feedback (Feedback), /admin/audit-log (Audit Log), /admin/campus-insights (Campus Insights), /admin/notifications (Notifications), /admin/config (Config), /admin/resources (Resources).

PERMISSION SEMANTICS (per page, 4 toggles):
- view = can open/read the page. If off, the page is blocked.
- edit = can create/update on the page. If off, hide/disable Add/Edit/Save buttons.
- delete = can delete. If off, hide/disable Delete buttons.
- hidden = remove the page from the sidebar AND block the URL entirely (overrides the rest).
- Super admins are never restricted by this map. Admins with `adminPermissions = null` get everything.
