PART 2 — CAMPUS INSIGHTS: 4 new columns + Week filter
==========================================================

The Campus Insights page (/admin/campus-insights) already exists. Extend
it with the 4 journal counters and a new Week filter.

2.1) NEW COLUMNS — add to BOTH tables.

VIEW A — "All campuses" (each row = one campus). New columns appended
after "Journals submitted":
   Campus name | No. of teams | Journals submitted |
   Clients visited | Active conversations | Projects started | Projects closed |
   Verified revenue (count) | Rejected revenue (count)

VIEW B — specific campus (each row = one team). New columns appended
after "Journal weeks submitted":
   Team name | Journal weeks submitted (X / total) |
   Clients visited | Active conversations | Projects started | Projects closed |
   Order book submitted (count) | Verified revenue (count) |
   Rejected revenue (count) | Total verified amount (₹)

Each new column is the SUM across the relevant rows in weekly_journals
(per campus for VIEW A, per team for VIEW B). Compute server-side in
the existing /api/admin/campus-insights endpoints — one SQL aggregation
per view, no N+1. Display as plain integers, right-aligned.

CSV exports (both "Campus-wise" and "All campuses (single CSV)") must
include the four new columns in the same order as the table, with
headers: "Clients visited", "Active conversations", "Projects started",
"Projects closed".

Sort tiering is unchanged.

2.2) WEEK FILTER

Add a new "Week" dropdown in the top filter row, immediately to the
RIGHT of the existing "Campus" filter (order: Search · Campus · Week · Export).

Default option: "All weeks" (selected by default; current behaviour).
Followed by one option per programme week, rendered as:
   "Week 1 (2026-04-07 → 2026-04-13)"
   "Week 2 (2026-04-14 → 2026-04-20)"
   ...
Pull week number + start/end dates from the programme_weeks table.
Sort ascending by week number. Format dates as YYYY-MM-DD.

Behaviour when a specific week is selected — every count and sum on
the page is scoped to that week's [startDate, endDate] inclusive range:
   * Journals submitted / Clients visited / Active conversations /
     Projects started / Projects closed → restricted to weekly_journals
     rows for that week.
   * Order book submitted (count) → order_book_entries where createdAt
     falls in the week.
   * Verified revenue (count) and Total verified amount →
     revenue_entries where status='verified' AND verifiedAt is in the week.
   * Rejected revenue (count) → revenue_entries where status='rejected'
     AND updatedAt is in the week.
   * "No. of teams" and the Journal-weeks-submitted denominator are NOT
     scoped — they remain programme-wide.
The week filter applies to BOTH VIEW A and VIEW B.

URL state: persist the selection in the query string as `&week=<n>`
(e.g. ?campus=3&week=5). "All weeks" omits the param. Refresh restores
the same view.

API: extend the existing endpoints to accept an optional `week` query
param:
   GET /api/admin/campus-insights?week=5
   GET /api/admin/campus-insights/:campusId?week=5
Validate the week exists in programme_weeks; invalid → 400.

CSV exports respect the current week selection. Filename includes the
week when one is selected, e.g.
   campus-insights-all-campuses-week5-2026-05-21.csv
Add a small note line at the top of the CSV before the header row, e.g.
   # Week: Week 5 (2026-05-13 → 2026-05-19)

PART 4 — ADMIN NOTIFICATIONS: subscriber list + daily overdue cron
==========================================================

A managed email subscriber list with a per-subscriber ON/OFF toggle,
plus a daily 09:00 IST cron that emails ENABLED subscribers a count
of OVERDUE revenue entries in the Review Queue. Whenever overdue
count is 0, send nothing.

REMINDER: do NOT modify /api/internal/cron/reminders or cron-reminders.ts.

4.1) DB — lib/db/src/schema/brave.ts. Add table:

  export const overdueNotificationSubscribersTable = pgTable(
    "overdue_notification_subscribers",
    {
      id: serial("id").primaryKey(),
      email: text("email").notNull(),
      isActive: boolean("is_active").notNull().default(true),
      addedBy: text("added_by").notNull(),
      createdAt: timestamp("created_at", { withTimezone: true })
        .notNull().defaultNow(),
      updatedAt: timestamp("updated_at", { withTimezone: true })
        .notNull().defaultNow().$onUpdate(() => new Date()),
    },
    (t) => [unique("overdue_notif_email_unique").on(t.email)],
  );

Run `pnpm --filter @workspace/db run push`.

4.2) New API route file:
artifacts/api-server/src/routes/admin-notifications.ts

Endpoints (admin-only, 403 otherwise):
  GET    /api/admin/notification-subscribers
         → list [{ id, email, isActive, addedBy, addedByName, createdAt }, ...]
           sorted createdAt DESC
  POST   /api/admin/notification-subscribers
         → body { email }; validate; lowercase+trim; 409 on duplicate
         → audit "add_overdue_notification_subscriber"
  PATCH  /api/admin/notification-subscribers/:id
         → body { isActive: boolean }
         → audit "toggle_overdue_notification_subscriber"
  DELETE /api/admin/notification-subscribers/:id
         → 204; 404 if missing
         → audit "remove_overdue_notification_subscriber"

Mount this router in artifacts/api-server/src/routes/index.ts WITHOUT
removing any existing mount.

4.3) NEW cron endpoint (separate from existing reminders):
  POST /api/internal/cron/overdue-notifications

Place handler in a NEW file:
artifacts/api-server/src/cron-overdue-notifications.ts. Do NOT touch
cron-reminders.ts. Wire it into routes/index.ts (additive).

Handler logic:
  1. Verify X-Cron-Secret header matches process.env.CRON_SECRET; else 401.
  2. Compute overdueCount = count of revenue_entries with
     status='submitted' AND submittedAt < now() - INTERVAL '<OVERDUE_DAYS> days'.
     USE THE SAME constant the admin Review Queue page uses — extract
     to a shared lib if needed, do NOT duplicate the number.
     Also compute totalPendingCount and oldestOverdueSubmittedAt.
  3. If overdueCount === 0:
       respond 202 { skipped: true, reason: "no overdue" }; send NO email.
  4. Else:
       Fetch subscribers WHERE isActive = true.
       If empty: respond 202 { skipped: true, reason: "no active subscribers" }.
       Render the email (template below). Send one email per active
       subscriber via the existing sendEmail() helper in
       lib/email/brevo.ts, batched 10 at a time with a 1-second pause
       between batches.
       Respond 202 { sent, failed, total, overdueCount }.
  5. Wrap DB/email work in try/catch; on error log and return 500
     { error: "Overdue reminder failed" }. Never throw out.

4.4) Email template — NEW FILE:
artifacts/api-server/src/lib/email/templates/overdue-reminder.ts

  type OverdueReminderInput = {
    recipientName?: string;
    overdueCount: number;
    totalPendingCount: number;
    oldestOverdueDate: string;     // DD MMM YYYY
    oldestOverdueDays: number;
    appUrl: string;
  };

  export function renderOverdueReminderEmail(input: OverdueReminderInput) {
    const subject = `BRAVE Review Queue — ${input.overdueCount} overdue revenue ${input.overdueCount === 1 ? 'entry' : 'entries'} pending`;
    const greeting = input.recipientName?.trim()
      ? `Hi ${input.recipientName.trim()},`
      : "Hi,";
    const lines = [
      greeting,
      "",
      `There ${input.overdueCount === 1 ? 'is' : 'are'} ${input.overdueCount} overdue revenue ${input.overdueCount === 1 ? 'entry' : 'entries'} waiting for verification on the BRAVE Dashboard Review Queue. Please review and verify (or reject) them at your earliest convenience.`,
      "",
      `  • Overdue items: ${input.overdueCount}`,
      `  • Total pending in queue: ${input.totalPendingCount}`,
      `  • Oldest overdue: ${input.oldestOverdueDate} (${input.oldestOverdueDays} days old)`,
      "",
      `Open the Review Queue: ${input.appUrl}/admin/queue`,
      "",
      "This is an automated daily reminder. It will keep arriving every day at 09:00 IST until the overdue count drops to zero.",
      "",
      "— BRAVE Team",
      "",
      "For any questions, reply to this email or contact brave.niat@nxtwave.in.",
    ];
    return { subject, text: lines.join("\n") };
  }
