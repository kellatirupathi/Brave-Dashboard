Build two new admin-only features on the BRAVE Dashboard's /admin/teams page: a manual "Add Team" dialog and a "Import CSV" bulk-upload dialog. These let an admin create real teams (leader + up to 4 members) on behalf of existing students using their Student User IDs. Imported/created teams are immediately active and visible to those students — no coordinator approval, no invitations, no join-requests.

This is purely additive. Do NOT change or break any existing flow: student-driven team creation, coordinator approval workflow, team join-requests, invitations, leave-requests, leaderboard, financials, demo-day, roster, or any existing API. Do NOT modify the database schema — all required columns already exist.

Stack context: pnpm monorepo. OpenAPI-driven (lib/api-spec/openapi.yaml → Orval codegen → lib/api-zod + lib/api-client-react). Express 5 API in artifacts/api-server. React + Vite + wouter + shadcn/ui frontend in artifacts/brave-dashboard. The users table in lib/db/src/schema/brave.ts already has campusId, niatId; teams table has status, inviteCode, leaderId, campusId, name; teamMembers table has unique (userId) constraint enforcing one-team-per-user.

=== BUSINESS RULES (confirmed) ===
1. Admin-created and admin-imported teams go straight to status = 'active'. No coordinator approval step.
2. Skip the entire row if ANY Student User ID in that row does not exist in the users table.
3. Skip the entire row if ANY user in that row is already a member of another team.
4. Duplicate team names are ALLOWED — do not enforce any team-name uniqueness check.
5. CSV format is wide: one row = one team, with leader + up to 4 additional members.
6. The Student User ID columns (UUIDs) are the source of truth for user linking. NIAT ID and Name columns in the CSV are display/reference only — do not use them for matching or validation.

=== EXACT CSV FORMAT TO ACCEPT ===
Header row (case-insensitive, matched by name not column index):
University | Student User ID | Team leader niat id | team leader Name |
Student User ID | Team member1 niat id | Team member1 Name |
Student User ID | Team member2 niat id | Team member2 Name |
Student User ID | Team member3 niat id | Team member3 Name |
Student User ID | Team member4 niat id | Team member4 Name |
Team Name | Total No.of Team Members

Mapping per row:
- "University" → universityName (look up in campuses table by name)
- 1st "Student User ID" column → leaderUserId
- 2nd-5th "Student User ID" columns → memberUserIds[] (skip blank cells)
- "Team Name" → teamName
- All "niat id" and "Name" columns → ignored for linking; used in preview UI only
- "Total No.of Team Members" → ignored; trust the actual non-empty cells

Skip trailing empty rows (where Team Name AND leader User ID are both blank).

STEP 2 — Backend
Create new file: artifacts/api-server/src/routes/admin-teams.ts

Both endpoints require admin role (use existing auth + role check pattern from admin.ts).

POST /admin/teams handler logic:
1. Validate body via the generated Zod schema from @workspace/api-zod
2. Verify campus exists by id; return 400 if not
3. Verify leaderUserId exists in users; return 400 if not
4. For each memberUserId: verify exists in users; return 400 if any missing
5. Build a deduped array [leaderUserId, ...memberUserIds]; verify none of them have an existing row in teamMembers; return 400 if any do
6. Generate unique inviteCode using the existing helper in teams.ts (extract or import it)
7. Insert teams row: { name, campusId, leaderId: leaderUserId, status: 'active', inviteCode }
8. Insert teamMembers rows for leader and each member (memberRole defaults to 'member', leader_id on the team makes leader detection work)
9. Insert auditLog row: { actorUserId: req.user.id, action: 'admin.team_created', targetType: 'team', targetId: newTeamId, details: { teamName, memberCount } }
10. Trigger the existing "team approved" auto-milestone (use the same helper used after coordinator approval in teams.ts)
11. Return 201 with the created team

POST /admin/teams/bulk-import handler logic:
1. Validate body
2. Process each row INDEPENDENTLY in a try/catch (no global transaction — partial success is desired)
3. Per row, run the same validation as the single endpoint:
   a. Resolve campus by name (case-insensitive trim); if not found → push to skipped with reason "Unknown university: <name>"
   b. Validate every User ID exists; if any missing → push to skipped with reason "User not found: <id>"
   c. Validate no User ID is already in teamMembers; if any are → push to skipped with reason "User already in team: <id>"
   d. If teamName is empty → push to skipped with reason "Team name required"
   e. If leaderUserId is empty → push to skipped with reason "Leader required"
4. If row passes: same insert path as single endpoint (team + members + milestone). Push to inserted[].
5. After all rows processed, write ONE summary auditLog: { action: 'admin.teams_bulk_imported', details: { totalRows, insertedCount, skippedCount } }
6. Return 200 with the AdminBulkImportTeamsResponse summary

Register the new router in artifacts/api-server/src/routes/index.ts:
  import adminTeamsRouter from "./admin-teams";
  router.use(adminTeamsRouter);
(Place after teamFlowRouter and teamsRouter — order does not conflict because these paths are /admin/teams which won't collide with /teams/:id.)
