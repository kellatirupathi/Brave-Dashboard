1. Bugs
🔴 High
B1. formatDate crashes the page on a bad/empty date — lib/format.ts:10
Unlike formatDateTime, formatDate has no validity guard, so new Date("") → .format() throws RangeError. It's used in render paths in projects list, project detail, and our new reels page (createdAt). With no error boundary in App.tsx, one malformed date white-screens the whole route.
Repro: any row whose date field is ""/null-coalesced server-side.
Fix: const d = new Date(s); if (Number.isNaN(d.getTime())) return ""; before formatting (mirror formatDateTime).

B2. Admin escalation can double-send — routes/cron-journal-escalation.ts:206-266
Admin dedup relies on a non-atomic SELECT-then-INSERT, and the onConflictDoNothing is a no-op because the unique key is (campusId, weekId, level) and campusId is NULL for admin (Postgres treats NULLs as distinct). Two near-simultaneous triggers both send the full admin blast.
Fix: unique partial index WHERE campus_id IS NULL on (week_id, level) (or store sentinel campusId=0), then rely on onConflictDoNothing; or wrap check+send+log in a txn with pg_advisory_lock(week|level).

B3. 🆕 Reel dedup only checks the newest 500 rows — lib/ai/generate-reels.ts:110
existingKeys is built from .limit(500) and reel_scripts.dedupeKey has no DB unique constraint. Once the library exceeds 500, the daily cron can re-insert a byte-identical older script.
Fix: add unique("reel_scripts_dedupe_unique").on(t.dedupeKey) and use .onConflictDoNothing({ target: reelScriptsTable.dedupeKey }). The 500-row prompt seed can stay.

B4. Fire-and-forget crons die on Replit autoscale + per-instance guards — cron-reels.ts, cron.ts, cron-backup-supabase.ts
202-then-background means the instance can be recycled mid-run (lost work), and the inFlight booleans only guard one process — with >1 replica, two runs overlap. Most dangerous for the Supabase backup (overlapping TRUNCATE…CASCADE).
Fix: durable lock (pg_try_advisory_lock/cron_locks row); for reels, add a catch-up sweep or run synchronously before responding (cron-job.org tolerates long requests).
