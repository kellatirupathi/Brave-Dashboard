Add an admin "Send test email" tool to verify Amazon SES is working.

Add a section on the admin Config page where an admin can type an email address, pick an email template, and send a test email — to confirm transactional email (Amazon SES) is delivering.

1. Backend — new endpoint

In artifacts/api-server/src/routes/admin.ts, add POST /api/admin/test-email.
Admin-only: reject with 403 if the user is not an admin.
Request body: { email: string, template: "revenue_verified" | "revenue_rejected" | "plain" } — validate it.
Behaviour:
revenue_verified → render the email using renderRevenueVerifiedEmail (from src/lib/email/templates/revenue-verified.ts) with sample/dummy data (e.g. recipientName "Test User", teamName "Test Team", amount 50000, clientName "Sample Client", projectTitle "Test Project", totalVerifiedRevenue 100000, adminNotes null, appUrl from getAppUrl()).
revenue_rejected → render using renderRevenueRejectedEmail (from revenue-rejected.ts) with dummy data + a sample reason.
plain → a simple subject "BRAVE — SES test email" and a short plain-text body confirming SES works.
Then call sendEmail({ to: { email }, subject, text }).
Respond { ok: true } if sendEmail returned true, else { ok: false, error: "Email failed — check SES config/logs" } with status 502.
Do not change sendEmail or any cron/financials code.
2. Frontend — admin Config page

In artifacts/brave-dashboard/src/pages/admin/config.tsx, add a new card/section at the bottom of the left column, titled "Email delivery test (Amazon SES)".
It contains:
A text input for the recipient email.
A template dropdown with options: "Plain test email", "Revenue verified", "Revenue rejected".
A "Send test email" button.
On click, fetch("/api/admin/test-email", { method: "POST", credentials: "include", headers: {"content-type":"application/json"}, body: JSON.stringify({ email, template }) }).
Show a success toast ("Test email sent — check the inbox") or an error toast with the returned message. Disable the button while sending and validate the email field is filled.
Match the existing Config page styling.
3. Run a typecheck on both packages after the change.

After the agent finishes — what you do
Make sure the 4 AWS secrets are set in Replit (AWS_REGION=ap-south-1, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, EMAIL_FROM).
Republish the app.
Log in as admin → go to Config page → in the new "Email delivery test" section:
Enter your own email → pick "Plain test email" → Send.
Check the inbox.
Interpreting the result:
✅ Email arrives → SES is working.
❌ Error toast → SES issue. Most likely cause: account still in sandbox (then test only works to a verified address) → request production access. Otherwise check the keys/region.
This gives you a permanent self-test button so you can confirm email health anytime without triggering a real revenue verify/reject.
